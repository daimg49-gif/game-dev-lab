## 一、《輔導室：今天也不能倒下》是什麼

你是國中唯一的專任輔導老師，從 08:00 撐到 17:00。學生、導師、家長、行政的需求一件件找上門，事情一定做不完，只能決定先接住誰。

規模：一個 HTML 檔，3,121 行，約 240 KB。沒有任何圖片檔，人物、地圖、圖示全部用程式畫出來。

### 它怎麼運作

| 系統 | 做法 |
|---|---|
| 地圖 | 40 × 22 格，每格 16 像素，俯視視角，鏡頭跟著主角 |
| 時間 | 遊戲內 1 分鐘＝現實 1.5 秒，一天 540 分鐘，大約玩 13.5 分鐘 |
| 數值 | 畫面上 4 條：精力、學生信任、行政完成度、內急；背後另有 2 個隱藏值（求助次數、界線） |
| 任務 | 20 件，分 5 種：主要、支線、限時、持續、交辦；另有 5 個隱藏成就 |
| 排程 | 一張時間表：第 5 分鐘小宇出現、第 40 分鐘林老師傳 LINE、第 120 分鐘分機響……依序觸發 |
| 對話 | 每個事件是一段腳本，台詞一句一句跑，遇到選項就停下來等玩家選 |
| 結局 | 7 種，放學時依數值與旗標判定，例如「信任低於 25 且錯過 5 件以上」走結局 E |
| 隱藏成就 | 5 個：好好吃午餐、讓自己喘口氣、說出界線、開口求助、看見不是個人的問題 |
| 道具 | 17 種，零食補精力、喝飲料會增加內急、帶著專業書籍有被動加成 |
| 遊戲內介面 | 仿手機（LINE 訊息、來電）、仿電腦（打紀錄）、背包、待辦清單 |
| 音效 | 全部用瀏覽器內建的 WebAudio 即時合成，沒有音檔 |
| 手機操作 | 左下方向鍵、右下互動大圓鈕 |
| 安全提醒 | 說明頁和結局頁都附衛福部安心專線 1925 |
| 測試接口 | 程式最後把主要函式掛在 `window.__CR`，讓自動測試可以直接呼叫 |

### 設計上最值得學的三件事

**選項沒有標準答案。** 小宇說不想回教室，三個選項是「先坐一下」「問發生什麼事」「陪他走回教室」，每個都合理，差別在花多少時間、信任和行政各加減多少。這正是校園溫度計要的「不像道德題」。

**懲罰來自取捨，不來自選錯。** 時間一直走，任務有期限。你陪學生沉默 15 分鐘換到一句真話，代價是另一件事逾期。玩家自己感受到「做不完」。

**結局講的是態度，不是分數。** 7 個結局裡有「把所有事做完了」，也有「不是所有事情都要一個人扛」。做完全部的人不一定拿到最好的結局。

## 二、兩款遊戲的共同骨架

農場是多人長期維護的開源專案（多檔、自動測試、AI 生圖），輔導室是一個人做的單檔作品，規模差很多。但拆開來看，骨架幾乎一樣：

| # | 共同點 | 農場 | 輔導室 |
|---|---|---|---|
| 1 | 純 HTML + CSS + JavaScript，不用框架 | ✓ | ✓ |
| 2 | 格子地圖、俯視、鏡頭跟隨 | 22 × 12 格 | 40 × 22 格 |
| 3 | 內容和引擎分開寫 | `config.js` 一個檔 | 角色表、道具表、任務表、結局表各一區 |
| 4 | 時間推動事件 | 現實時間戳 | 遊戲內時鐘＋時間表 |
| 5 | 數值記帳都走同一個函式 | 統一結算規則 | 所有加減都經過 `fx()` |
| 6 | 旗標記住玩家做過什麼 | `flags` | `S.f` |
| 7 | 走到目標旁邊才能互動 | 明文規定「先走近才結算」 | 靠近才出現互動提示 |
| 8 | 任務分種類，有清單 | 3 章 9 個主線任務 | 5 種任務類型＋隱藏成就 |
| 9 | 手機和電腦都能玩 | 底部按鍵列 | 方向鍵＋互動鈕 |
| 10 | 預留測試接口 | Node 測試＋瀏覽器自動測試 | `window.__CR` |

差異只有一個值得特別記：**美術**。農場用 AI 生圖再切割，要 API 金鑰和處理腳本；輔導室用程式畫像素人，每個角色只是一行設定（膚色、髮型、上衣顏色、有沒有眼鏡）。後者完全符合 Pei「單一 HTML 檔、直接部署」的習慣。

## 三、往後的開發範本：五層骨架

每做一款新遊戲，照這五層拆。用積木架構法對照：

| 層 | 內容 | 積木 | 換主題時要改嗎 |
|---|---|---|---|
| ① 內容表 | 角色表、道具表、任務表、事件腳本、時間表、結局表 | 工具箱（資料） | **只改這層** |
| ② 規則 | 時鐘、數值結算 `fx()`、旗標、任務期限、結局判定 | 守門（邏輯） | 少量調整 |
| ③ 畫面 | 地圖格子、程式畫的像素人、HUD、對話框、手機操作 | 入口（展示） | 換地圖配置與配色 |
| ④ 底座 | 單一 HTML、localStorage、GitHub Pages | 地基 | 不改 |
| ⑤ 測試 | `window.__GAME` 測試接口＋回歸測試清單 | 測試積木 | 隨內容增加條目 |

### 校園溫度計可以吸收的做法

校園溫度計已經有雙線索事件卡、溫度後台結算、每天 5 件自己的事。對照輔導室，還可以加：

1. **時間表觸發**：把「第幾分鐘發生什麼事」寫成一張表，事件不再只靠玩家走到才觸發
2. **隱藏成就**：例如「主動陪小恩吃午餐」，放學結算才揭曉
3. **多結局判定**：放學依溫度與旗標分 4～6 種結局，每個結局講一種待人方式
4. **程式畫角色**：用設定表畫像素人，換角色只改一行，不必找圖
5. **測試接口**：讓 Claude 每次修改後能自動跑完一天，確認沒有卡關

這 5 項要不要做、先做哪個，交 Pei 決定。

## 四、新遊戲開工流程

| 步驟 | 誰 | 產出 |
|---|---|---|
| 1. 填企劃單（下方） | Pei | `docs/specs/<遊戲代號>.md` |
| 2. 寫內容表初稿：角色、事件卡、結局 | ChatGPT | `docs/reviews/CHATGPT_DRAFT_<代號>_R1.md` |
| 3. 查證初稿、套進五層骨架、做出可玩版 | Claude | 遊戲 repo 的 v1 |
| 4. 試玩後審查 | ChatGPT | `docs/reviews/CHATGPT_REVIEW_<代號>_R1.md` |
| 5. 逐條回應與修改 | Claude | `docs/responses/CLAUDE_RESPONSE_<代號>_R1.md` |
| 6. 裁決 | Pei | `docs/decisions.md` |
| 7. 上線 | Claude | GitHub Pages 新版 |

開工前記得：新遊戲先開新 repo，避免蓋掉已完成的遊戲。

### 企劃單（Pei 填，每款遊戲一份）

```markdown
# <遊戲名稱> 企劃單

- 遊戲代號（英文小寫，當 repo 名稱）：
- 給哪個年級玩：
- 一次玩多久：
- 教學目標（學生玩完要帶走什麼）：
- 主角是誰、在哪裡、一天從幾點到幾點：
- 會遇到哪些人（虛構名字）：
- 想放進去的情境（3～10 個，一句話描述即可）：
- 要追蹤哪些數值（例如溫度、信任、精力）：
- 結局想傳達的想法：
- 不要出現的東西：
- 參考作品（可附連結）：
```
