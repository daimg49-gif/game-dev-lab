# 分析：《fab24hr 半導體晶圓廠打工人的一天》是怎麼做出來的

- 分析對象：https://fab24hr.com/ （作者 Threads 帳號 @mrclty，個人作品）
- 分析日期：2026-10-15
- 分析者：Claude（給 Pei、ChatGPT 共同閱讀）
- 資料來源：遊戲首頁與 7 個說明頁（about、day、people、glossary、teach、press、sitemap.xml），加上 Pei 2026-10-15 的實際遊玩結果

## 零、先講清楚哪些是確定的

這次**讀不到原始碼**。工作環境連不上 fab24hr.com，網頁讀取工具只拿得到文字、拿不到程式；作者也沒有公開 GitHub repo。所以本文分三種確定程度：

| 標記 | 意思 |
|---|---|
| ✅ 確定 | 作者在說明頁自己寫的，或從網頁標籤直接看得到 |
| 🔍 推測 | 從遊戲行為推回去的做法，沒看到程式碼 |
| ❓ 不知道 | 作者沒公開，本文不猜 |

例如「用什麼 3D 引擎」「AI 用在哪些環節」都是 ❓。作者只說「這個遊戲是作者跟 AI 一起做的」，Buy Me a Coffee 的款項用來付 AI 使用費。

## 一、它是什麼

一款 3D 劇情模擬遊戲，你當一天晶圓廠工程師。凌晨 02:47 電話響了，機台亮紅燈，所有人都在等你給一個時間。

| 項目 | 內容 |
|---|---|
| 上線 | 2026-10-04 ✅；sitemap 最後更新 2026-10-14 ✅，上線 10 天內仍在改 |
| 平台 | 手機、平板、電腦瀏覽器，免安裝、免登入、無廣告 ✅ |
| 語言 | 繁中、英文、日文，三語各有一套網址（/、/en/、/ja/）✅ |
| 一班長度 | 5～15 分鐘 ✅ |
| 可玩角色 | 6 個：製程、製造部、設備、黃光、研發整合、研發製程 ✅ |
| 不可玩但有出場 | 技術員、製程整合、課長、廠商工程師 ✅ |
| 行話解釋 | 91 個詞條（約 95 個詞）✅ |

作者的定位講得很明白：同類晶片遊戲大多是蓋廠、經營，這款是劇情模擬，你是被叫醒的工程師，不是老闆。

## 二、故事設計

### 1. 一天切成四班，班別跟著裝置時鐘走

| 班 | 時段 | 標題 | 在做什麼 |
|---|---|---|---|
| 深夜 | 00:00–05:59 | 那通電話 | 人在家，隔著電話指揮夜班同事 |
| 早 | 06:00–11:59 | 救火 | 進廠、查原因、測機、復機 |
| 午 | 12:00–17:59 | 趕時間 | 手動補做晶圓，然後開檢討會 |
| 晚 | 18:00–23:59 | 下班未遂 | 一直被叫住，最後看到一顆黃燈 |

✅ 教師頁寫到「班別跟著裝置時鐘」：早上上課的班級玩到早班。Pei 在 00:14 打開，所以進的是深夜班。

這招讓遊戲像「現在正在發生」。缺點是想玩特定班別要換時間開，作者用「接續玩完整天」補上。

### 2. 分數是「幾點下班」

每個選擇都會花遊戲時間，結算看的是你幾點下班、加班多久。Pei 的結果：

> 凌晨 02:47 被電話叫醒，04:08 才躺回去。離鬧鐘響還有 2 小時 22 分。

沒有分數，代價直接換成玩家感受得到的東西：睡眠少了多少。press 頁的截圖裡，晚班結算卡寫著加班 2 小時 13 分。

### 3. 稱號描述你「怎麼做」，不評好壞

Pei 拿到的稱號「隔著電話救火」、成就「第一聲就接起來」「半夜先問人」，都是在描述行為。教師頁寫明：沒有測驗、沒有分數，結算卡給一個「描述你做了哪些選擇」的稱號。

跟《輔導室》的「結局講態度」、《情緒偵探社》的「偵探評語」是同一個方向，只是更短，短到可以分享。

### 4. 隨機突發事件，選項本身會被記住

Pei 這班遇到「半夜地震・先問人」：事件名稱加上你選的做法，一起寫進結算。press 頁列出的其他突發事件有電壓驟降、晶圓掉落 ✅。

🔍 推測結構：每班有一個固定主線，外加從事件池抽 1 件突發事件；每個選項帶一個短標籤（如「先問人」），結算時拿標籤組成文字與成就。

### 5. 同一件事，六個位子各看一遍

day 頁把同一天切成 12 個時間點（02:47 電話、07:30 交接、08:30 早會、13:58 人為操作失誤……19:25 交接給夜班），每個時間點寫出製程、設備、製造部、整合、課長各自在做什麼 ✅。

研發線的設定更進一步：研發線試產的晶片，半年後有一批變成量產廠的急件 H-2417 ✅。玩研發線的人做的決定，就是量產廠那通電話的源頭。

教師頁的 40 分鐘教案就是靠這個設計：3～4 人一組各選不同角色玩同一班，再比較「機台倒下那一刻，每個角色看到什麼、擔心什麼」。

### 6. 寫實感從哪裡來

- **具體時間戳**：02:47、04:08、13:58，到分鐘
- **具體代號**：ETCH-03 CH-A、WET-02、H-2417
- **行話照講，點了才解釋**：對話裡有虛線的詞點一下跳出白話說明，跟 glossary 頁同一份文字 ✅
- **人物說明頁的固定格式**：簡介 → 一天怎麼過（附時間）→ 最怕的事（2～3 條）→ 在遊戲裡 ✅

「最怕的事」這一欄很值得學，三行就讓角色有了動機。

## 三、程式概念

### 確定看得到的部分

| 功能 | 做法 | 對照積木 |
|---|---|---|
| 移動 | 方向鍵、WASD、點地板；走近按 E 對話 ✅ | 入口 |
| 導引 | 目標人物或機台頭上有「！」；「帶我去」按鈕自動走過去 ✅ | 入口 |
| 3D 失敗備援 | 3D 打不開時遊戲內容照常進行 ✅ | 守門 |
| 存檔 | 進度存在瀏覽器，離開可接續 ✅ | 地基 |
| 匿名統計 | 瀏覽器存一組隨機代號，記錄進度、選擇、裝置、3D 載入狀況；不用 cookie、不記名字 ✅ | 工具箱（記憶） |
| 問題回報 | 自動附上螢幕大小、瀏覽器、畫質、語言、最近的程式錯誤 ✅ | 錯誤記錄 |
| 分享 | 9:16 結算圖卡（限時動態尺寸）、分享連結、複製文字三種 ✅ | 入口 |
| 手機畫面 | viewport 設定禁止縮放、`viewport-fit=cover` 處理瀏海 ✅ | 入口 |
| 多語 | 三語各一套靜態網址，用 hreflang 互相標示 ✅ | 地基 |

### 推測的架構 🔍

「3D 打不開仍可玩」透露最關鍵的一點：**劇情邏輯完全不依賴 3D 畫面**。3D 場景只是表演層，對話、選項、時間、結算都在另一層跑。這跟《輔導室》《農場》的「內容與引擎分開」是同一件事，只是分得更徹底。

推回去大概是這樣：

```
劇情資料（每個角色 × 四班 × 對話、選項、時間花費、標籤）
        ↓
規則層（遊戲時鐘、選項扣時間、突發事件抽籤、成就判定、結算文字）
        ↓
表演層 A：3D 場景（失敗就關掉）
表演層 B：文字介面（對話框、選項、結算卡）← 永遠在
```

結算卡可能是用 canvas 把文字畫成圖再存檔 🔍，網址參數 `?utm_source=share` 用來分辨玩家從哪裡來 ✅。

### 不知道的 ❓

3D 引擎名稱、檔案拆法、有沒有自動測試、AI 在寫程式／寫劇情／做美術各佔多少。

## 四、美術

能確定的只有 press 頁的 7 張截圖描述與網頁設定：

| 截圖 | 畫面 |
|---|---|
| 1 | 昏暗臥室，床邊手機亮起 |
| 2 | 更衣室，選無塵衣顏色 |
| 3 | 清洗機 WET-02 亮紅燈，對話框兩個選項 |
| 4 | 穿無塵衣的角色跌倒，晶圓碎在地上 |
| 5 | 地震警報，一排機台燈號轉黃 |
| 6 | 晚班結算卡「看見黃燈的人」，加班 2 小時 13 分 |
| 7 | 「今天你是」角色卡，「換個位子」列表，每個位子一行說明 |

看得出三件事：

1. **燈號就是語言**：紅燈＝出事、黃燈＝要注意。玩家不懂半導體，也看得懂燈號。
2. **暗色調**：網頁主題色 `#0c151a`（深藍黑），配合深夜開場。
3. **讓玩家選一件小東西**：無塵衣顏色。成本很低，玩家卻會覺得那是「我」。

宣傳素材準備得很完整：兩支 1080×1920 直式影片（中、英字幕，刻意不放音樂讓創作者自己配）、1200×630 分享預覽圖、512×512 圖示 ✅。

## 七、Pei 可以借用的

### 建議借用

1. **代價換成生活時間**：情緒偵探社的「主角情緒累積」可以改成「放學時，你還有多少力氣寫功課」這類學生懂的代價，取代數值條。
2. **行為稱號**：結案報告加一行稱號，例如「先蹲下來看的人」「第一句就問怎麼了」。只描述做了什麼，不評好壞。
3. **選項帶標籤**：每個選項附一個 2～5 字的標籤（「先問人」「先離開」），結算時把標籤組成句子。寫事件卡時多填一欄就好，成本很低。
4. **同一件事多個位子**：霸凌情境特別適合。同一個下課 10 分鐘，分別用被欺負的人、旁觀者、班長、導師的位子玩一次。40 分鐘課可以照 fab24hr 的分組比較法。
5. **詞語點擊解釋**：情緒細詞（委屈、捨不得、被冒犯）在對話裡加虛線，點了跳出白話說明，內容跟情緒圖鑑共用一份資料。
6. **人物「最怕的事」欄**：角色表多一欄，每個委託人寫 2～3 條，寫腳本時不容易讓角色變成工具人。
7. **教師頁**：每款遊戲在 GitHub Pages 多放一頁「在課堂上玩」，寫 20／40 分鐘流程和 3～5 個討論題，其他老師拿了就能用。

### 建議先不要

1. **3D 場景**：成本高，平板效能也不一定撐得住。程式畫像素已經夠用。
2. **依裝置時鐘選班**：學校上課時間固定，學生每次都會玩到同一段，反而少了變化。
3. **匿名統計選擇**：要有後端收資料，GitHub Pages 做不到；改用 GAS 收也牽涉學生資料，先不碰。
4. **社群分享**：學生在校平板不適合分享到社群。結算圖卡可以保留，改成「存圖交給老師」。
5. **三語版本**：目前對象只有本校學生。

### 已經在做、可以加強的

情緒偵探社規格書第八節已有「錯誤記錄積木：畫面角落顯示錯誤代碼」。可以學 fab24hr 多附幾項：裝置螢幕大小、瀏覽器、最後一個錯誤訊息，Pei 截一張圖 Claude 就能定位問題。
