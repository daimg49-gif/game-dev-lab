## 二、故事設計

### 1. 每一關都是「開學第一天」

三關的時間都是 9 月 1 日早上，地點都是一所虛構國中的七年級教室 ✅。玩家不用先理解角色的背景，開學第一天的緊張感每個人都有，困難是疊在這份共同經驗上的。

### 2. 暖身：同一句話，四種收法

主選單的「暖身」是整套作品最精巧的入口 ✅。黑板上一句話「各位同學，把聯絡簿拿出來，寫好名字，放到講桌上」，下面四顆按鈕：

| 模式 | 畫面怎麼變 |
|---|---|
| 原本的話 | 正常顯示 |
| 太大聲 | 「叮——咚——」「喀啦！」「哈哈哈」一直冒出來蓋住句子 |
| 被拉走 | 句子切成 6 段，每一段有 45% 機率隨機消失；旁邊浮出「那隻鳥是麻雀嗎？」這類念頭 |
| 字會跳 | 每個字分開跳動 |

一個畫面、一句話、30 秒，玩家就懂了三關各自在講什麼。給老師的 45 分鐘流程也用它當開場 5 分鐘 ✅。

### 3. 每個困難都配一個真實的校園時刻

以第 1 關為例，結束後會列出今天遇到的 6 個時刻，每一則固定三行 ✅：

| 欄 | 範例 |
|---|---|
| 時刻 | 「你很酷欸」 |
| 發生什麼、為什麼 | 你照字面回答「我不冷」，結果被笑了。比喻、反話和玩笑，可能被照字面理解。 |
| 同學可以 | 直接說出你真正的意思；他沒跟著笑，不代表不友善。 |

第二行會依玩家剛才的選擇換內容 ✅（回答「我不冷」、猜是稱讚、不說話，三種各一句）。所以結算頁講的是「你剛剛經歷的事」，不是一段通用說明。

第三行「同學可以：」是用 CSS 自動加上去的標籤 ✅，每個時刻都一定要寫一個旁人做得到的小動作。

### 4. 困難和長處寫在同一段

第 1 關結算頁有一段「你也注意到了……」：黑板時鐘慢了三分鐘、牆上磁磚少一塊、你記得每顆星星的名字。後面接一句「困難和長處，常常是同一顆大腦的兩面」✅。

這段很短，但它把「感官很敏銳」同時呈現成負擔和能力。對 Pei 要做的資優主題，這是最值得學的一段（見第七節）。

### 5. 名字本身就是謎題

第 3 關要在公佈欄找自己的班級，名單上同時有「林小安」「林少安」「材小安」「林小宇」「材小平」✅。座位表也有三個空位分別是林小安、林少安、材小安 ✅。

程式裡有一張「長得像的字」對照表 `CONF`，約 120 個字各配 1～3 個易混字（林↔材、小↔少、b↔d、6↔9）✅。字跳動時就從這張表換字。玩家不需要被告知「這是識字困難」，自己會在三個名字之間猶豫。

### 6. 第二輪才是重點：支持模式

三關都可以「再過一次同一天」，第二次換成有支持的版本 ✅：

| 關卡 | 支持模式改了什麼 |
|---|---|
| 分心的第一天 | 座位從窗邊換到前排中間；分心事件間隔從 3～5.5 秒拉長到 9～13 秒；沒有漫畫、籃球這類誘惑物；交代的事不會從清單上淡掉 ✅ |
| 小安的開學日 | 老師說話變慢；重點寫上黑板；教室變安靜；學長用手指著名單上那一行；抄聯絡簿時另給一張作業單；壓力上升只剩 35% ✅ |
| 世界太大聲的一天 | 沒有獨立的支持模式；改成玩家自己用耳罩、深呼吸、看課表來調節 ✅ |

第 2 關結算時兩輪並排成一張表比較 ✅。討論題直接問「有支持和沒有支持，差在哪裡？哪一項改變最有用？」✅

這就是「看見環境」的落實：同一個人、同一天，換了座位和老師的說法就做得到。

## 三、互動方式

### 1. 各關的核心機制

| 關卡 | 主要數值 | 玩家能做的調節 | 失控時 |
|---|---|---|---|
| 太大聲 | 感官負荷 0～100，分「平靜／有點緊繃／很不舒服／快要受不了／超載」五段文字 ✅ | Q 戴耳罩（噪音小，但別人的話也聽不清）、按住 F 深呼吸、Tab 看課表 ✅ | 超載：畫面白閃、晃動，跳出說明「剛剛發生的是感官超載」✅ |
| 分心 | 專注、坐不住、下課倒數 ✅ | Q 回想交代的事、按住空白鍵「停一下想一想」、F 動一動 ✅ | 被誘惑物吸走時跳出一段旁白，例如「你翻開漫畫……回過神來已經過了好幾分鐘」✅ |
| 字會跳 | 緊張程度 ✅ | 1～4 選字抄聯絡簿 ✅ | 字跳得更兇、選錯字 |

**每一個調節都有代價**：耳罩讓你聽不清楚老師；深呼吸要站著不動；查課表會停下腳步。玩家體會到的是「自我調節要付出力氣」。

### 2. 聽不完整用「▒」表現

第 3 關老師交代明天要帶的東西，有 3 段（「還有剪刀」「請爸爸媽媽簽名」「也要帶水壺」）會被干擾聲蓋掉 ✅。字幕上那段變成「▒▒▒▒」，旁邊附「（後面同學拉椅子：嘰——）」，同時真的播出拉椅子聲 ✅。玩家事後要抄聯絡簿，才發現自己漏了什麼。

### 3. 念頭浮在畫面上

第 2 關每隔幾秒，畫面上隨機位置浮出一句念頭：「我剛剛要幹嘛？」「大家是不是在看我？」「腳好癢」✅。分心事件發生時，視角會被慢慢拉向聲音來源（鳥、紙飛機、走廊跑過的人）✅，玩家要自己把頭轉回來。

### 4. 聲音全部用程式即時合成

- 教室的人聲嘈雜：用 7 組母音共振頻率合成「聽起來像講話但聽不出字」的聲音 ✅
- 每個角色有自己的音高（陳老師 170、打菜阿姨 230……）✅
- 第 2、3 關老師說話用瀏覽器內建的語音朗讀 ✅，支持模式語速放慢（1.32 倍 → 0.9 倍）✅
- 「超載」的轟鳴聲刻意繞過耳罩濾波，因為那是腦內的聲音 ✅

### 5. 安全與無障礙

| 做法 | 位置 |
|---|---|
| 開始前提醒「有突然的大聲響與閃白畫面」，可勾「減少閃爍與晃動」✅ | 第 1 關開場、老師頁 |
| 偵測系統的「減少動態效果」設定，自動降低特效 ✅ | 4 個檔案都有 |
| 減少閃爍時白閃強度只剩 12% ✅ | 第 1 關 |
| 鍵盤可以操作整個主選單 ✅ | 首頁 |
| 每關結尾都寫「只模擬部分經驗，不能代表任何一個人」✅ | 全部 |

## 四、程式概念

### 1. 整體架構 ✅

```
index.html（主選單）
  ├ 背景：一間 3D 教室一直在跑，切換畫面時鏡頭飛到不同位置
  ├ 四個畫面：主選單、選關、暖身、給老師（用網址 #levels、#warmup、#teacher 切換）
  └ 讀 localStorage 顯示哪幾關「已完成」
        ↓ 點關卡，直接換頁
loud-day.html / focus-day.html / reading-day.html
  各自獨立，互不呼叫；作者明講「改一個不會影響其他」
```

每一關內部是同一種結構：

```
資料表   台詞（LINES／SENT）、分心事件（DEFS）、誘惑物（DECOYS、STIM）、易混字（CONF）、結算時刻（M）
   ↓
模式設定  CFG.sim / CFG.support（或 G.acc 開關）← 支持模式只是換一組參數
   ↓
劇情流程  用 async/await 一段一段跑：say() 說話 → think() 內心話 → choose() 選擇 → addLoad() 加減負荷
   ↓
3D 畫面   three.js 用方塊、圓柱、球組出教室和人，文字畫在 canvas 再貼上去
   ↓
結算頁   依剛才的選擇組出「今天你遇到的時刻」與討論題
```

### 2. 最值得學的一招：支持模式＝換一組參數

第 2 關把兩種模式寫成同一個設定物件的兩組值 ✅：

| 參數 | 體驗模式 | 支持模式 |
|---|---|---|
| 座位 | 窗邊 | 前排中間 |
| 分心事件間隔 | 3～5.5 秒 | 9～13 秒 |
| 分心拉力 | 1.6 | 0.5 |
| 分心來源 | 鳥、筆聲、門口、紙飛機、悄悄話、時鐘、吊扇 | 只剩筆聲、門口、時鐘、吊扇 |
| 誘惑物 | 有 | 無 |
| 允許小動作 | 否 | 是 |

劇情程式只寫一份，每次讀 `C()` 拿目前模式的參數 ✅。要多加一種「部分支持」，只要多寫一組參數。

這跟 Pei 的「工具箱（資料）與守門（邏輯）分開」完全一致，而且做得更徹底：**「環境調整」這個教學概念，在程式裡就是一張參數表**。

### 3. 劇情用 await 串起來

第 1 關的劇情幾乎是一行一句 ✅：

```
await say('阿哲','哈哈哈哈！你好好笑喔！',2.6);
await think('他為什麼笑？我說錯什麼了嗎？「酷」不是冷的意思嗎？',4);
addLoad(6);
```

讀起來像劇本，改台詞不必懂 3D。Pei 或 ChatGPT 寫好腳本，Claude 可以幾乎原樣轉成程式。

### 4. 3D 美術完全程式畫

人物是一顆球當頭、半顆球當頭髮、方塊當身體，膚色和髮色從 4 種裡隨機挑 ✅。黑板、海報、名單都是先在 canvas 畫字再貼到 3D 平面上 ✅。所以整套作品沒有任何圖檔。

### 5. 小問題

- 第 1 關用 three.js 0.149，其他三個用 r128，作者自己在 README 提醒「程式碼不能直接在檔案之間複製」✅。這是快速開發留下的債。
- 有 `window.__FX` 之類的接口 🔍，可能是特效開關或測試用，沒有像 hesen-mail 那樣的自動解題函式。
- 平板效能 ❓：有陰影、霧、粒子、後製特效，舊平板可能吃力。

## 六、Pei 可以借用的（一般設計手法）

### 建議借用

1. **暖身「同一句話」**：任何多視角遊戲都可以先做一個 30 秒的單畫面，一句話、幾顆按鈕切換。成本最低、效果最直接。
2. **支持模式＝參數表**：情緒偵探社的「家庭支持高／低」、校園溫度計的「班級氣氛好／不好」，都可以寫成兩組參數讓學生比較。
3. **結算三欄固定格式**：時刻／為什麼／同學可以。第三欄強制寫一個旁人做得到的小動作。
4. **困難和長處寫在同一段**：每個角色的結算加一段「你也注意到了……」。
5. **劇情用 await 寫成劇本**：`say()`、`think()`、`choose()` 三個函式就能撐起整段劇情，ChatGPT 寫的腳本可以直接對應。
6. **內心話和說出口的話分開**：`say` 是對白，`think` 是內心話，用不同樣式顯示。SEL 遊戲很需要這一層。
7. **三個約定放在玩之前**：首頁選關畫面就列出來，不藏在說明頁。
8. **減少閃爍開關＋系統動態偏好**：往後有特效的遊戲都加。

### 建議先不要

1. **3D 第一人稱**：平板效能和三到六年級的操作負擔都是問題（WASD＋滑鼠轉頭、搖桿＋拖曳）。用 2D 俯視或點選式場景，一樣做得出「支持模式」的比較。
2. **大量語音朗讀**：瀏覽器內建語音在不同平板上音色差很多，課堂上 25 台一起念也很吵。改成字幕為主、需要時再開。
3. **閃白和超載特效**：國小中年級要更輕。

## 七、針對「讓人認識資優生」的建議

### 1. 先想清楚：要讓誰認識？

這款的玩家是「普通班同學」，目標是讓他們理解身邊的人。用在資優主題，至少有三種玩家，設計方向完全不同：

| 玩家 | 他們需要帶走什麼 | Pei 手上接得上的工作 |
|---|---|---|
| 普通班同學 | 資優生不是什麼都會；有些反應背後有原因；我可以做哪件小事 | 優普合作、入班宣導 |
| 普通班導師 | 這位學生在原班的哪些時刻會卡住；哪些調整成本很低 | 資普聯繫通知單、優普合作會議 |
| 資優生本人 | 我不是怪；這些感受有名字；我可以怎麼跟別人說 | 「認識資優」新生單元 |

我建議**第一版做給普通班導師與同學看**，理由是《認識多元的世界》已經證明這個形式對「旁人」有效，而且資優生本人的版本已經有「認識資優」單元在處理。

### 2. 最大的風險：貼標籤

作者的第一條原則是「不指名任何障別或診斷」。資優主題正好踩在這條線上：

- 遊戲一寫「資優生的一天」，普通班學生就會拿去對照班上那幾位，等於公開身分
- 「資優」容易被理解成「比較聰明」，同學可能產生「他都會，為什麼還要幫他」的反應
- 資優生本人可能不喜歡被當成「需要被理解的對象」

我的建議做法：**遊戲裡不出現「資優」兩個字**，照原作的方式只描述感受。例如關卡叫「想得太快的一天」「感受太強的一天」，結算頁最後才帶一句「有些人的大腦就是這樣運作，想了解就問本人」。

這跟《看見小宇宙》結果頁「不直說孩子不好」的原則同一個方向：描述行為和需要，不給標籤。

### 3. 三個可以做的關卡

以下是常被資優教育文獻提到的經驗，每個都配一個國小校園時刻和一組「支持模式」參數：

| 關卡 | 校園時刻 | 體驗模式 | 支持模式 |
|---|---|---|---|
| **早就會了的一天**（學習速度與無聊） | 老師講第三遍已經會的單元 | 「無聊條」慢慢上升；念頭一直冒出新問題；舉手被說「等一下再問」；忍不住講出答案被同學說「愛現」 | 先做完可以拿延伸任務單；問題可以寫在「問題停車場」；老師說「這題下課跟我聊」 |
| **想做到完美的一天**（完美主義） | 美勞作品、聯絡簿、考卷 | 一筆不滿意就想擦掉重來，時間一直流走；考 95 分被同學說「你不是資優嗎」 | 老師先說「今天練習的是草稿」；作品可以分兩次完成；同學改說「你哪一題最有成就感？」 |
| **感受太強的一天**（情緒與公平敏感） | 分組時有人被排擠、遊戲規則不公平 | 「情緒條」比同學升得快很多；別人覺得沒什麼的事，你很在意 | 有一個可以去冷靜的角落；老師願意聽你說完為什麼覺得不公平 |

文獻依據可以這樣對應（正式寫教師頁時再附完整書目）：

- **情緒與感受強烈**：波蘭心理學家 Kazimierz Dąbrowski 提出的「過度激動特質」（overexcitabilities），後來由 Michael Piechowski 引入資優教育研究
- **想法跑在手和情緒前面**：1991 年 Columbus Group 提出的「非同步發展」（asynchronous development）概念
- **完美主義**：資優情意教育長期討論的主題，不同研究對「資優生是否比較完美主義」結論不一致，教師頁要照實寫「研究結果不一致」

### 4. 最值得移植的一段：困難和長處在同一顆大腦

原作只用一段話帶過「困難和長處常常是同一顆大腦的兩面」。資優主題可以把它做成結算頁的主體：

| 剛才讓你卡住的 | 同一件事的另一面 |
|---|---|
| 一直冒出新問題，被說不專心 | 好奇心和連結能力 |
| 擦掉重來十次 | 對品質有很高的要求 |
| 為不公平的事生氣很久 | 很強的正義感 |

這張表就是 Pei 在「認識資優」單元說的「資優特質可能帶來的困擾」。同一份資料表可以兩邊共用。

### 5. 「問本人」可以做得更徹底

原作的「問本人」只是一句提醒。資優班可以讓學生自己寫關卡：

- 每位資優生寫一個「我在原班最卡的時刻」和「我希望同學怎麼做」
- Pei 篩選、去識別化後，變成遊戲裡的時刻卡
- 結算頁註明「這些時刻是真的資優班學生寫的，但不代表任何一位」

這樣遊戲裡的內容來自本人，資優生也從「被理解的對象」變成「設計者」。可以接在凱比機器人課或「認識資優」單元當產出。

### 6. 技術做法（積木架構法）

| 積木 | 做法 |
|---|---|
| 入口（展示） | 2D 教室場景、點選式互動，不用 3D 和搖桿；平板橫向；開頭「同一句話」暖身 |
| 守門（邏輯） | 一套劇情程式＋兩組參數（體驗／支持）；三條數值：無聊、時間、情緒 |
| 地基（部署） | 單一 HTML、localStorage 只記完成關卡、GitHub Pages 新 repo |
| 工具箱（資料） | 時刻卡表（時刻／為什麼／同學可以）、念頭表、困難↔長處對照表 |
| 測試積木 | 每關一條自動跑完的路線，兩種模式各跑一次 |
| 錯誤記錄積木 | 角落顯示錯誤代碼＋裝置資訊 |

周邊頁照原作做「給帶領的老師」：三個約定、40 分鐘流程、4 個討論題、出處列表。
