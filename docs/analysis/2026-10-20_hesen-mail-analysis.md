## 一、它是什麼

一個長得像公司網頁信箱的解謎遊戲。分享標題寫「上班也能玩」，瀏覽器分頁顯示「收件匣 (7) - staff.2047@…」✅，旁人瞄到螢幕只會以為你在收信。

故事：有人盜用你的公司帳號，把標案底價寄到外面，再冒充客戶寫信威脅你。你要表面配合、暗中反擊，把真正的人抓出來 ✅。

| 項目 | 內容 |
|---|---|
| 檔案 | `index.html` 一個檔 1,533 行、約 436 KB；另有分享預覽圖 `og.png`（1200×630）✅ |
| 圖片 | 只有 1 張 AI 生成的照片，用 base64 塞進 HTML，就佔了約 259 KB；其餘圖示、海報、表格、網站全部用 SVG 和 HTML 畫 ✅ |
| 外部資源 | 只有 Google Fonts 的 Roboto 字型 ✅ |
| 開發節奏 | 7 個 commit。10-14 下午 14:49～15:26 連推 4 個（初版、登入頁改版、分享預覽圖），10-20 上午再修 3 個（手機版跑版、摘要提示加深、拿掉 Esc 老闆鍵）✅ |
| 存檔 | localStorage，存檔名稱 `inboxthriller.v4`，代表內部至少改過 4 版存檔格式 ✅ |
| 謎題數 | 18 道要回信的謎題，外加 1 道按按鈕的謎題 ✅ |
| 一輪長度 | 程式會算花費分鐘數，但沒有預設值 ❓ |

### 開發工具的痕跡 🔍

程式裡有兩行在呼叫 `window.claude.hot`，用來在重新載入時保留遊戲狀態 ✅。這是 Claude 的 artifact 預覽環境才有的接口，代表作者很可能是在 Claude 裡一邊預覽一邊改，最後再把 HTML 推上 GitHub Pages 🔍。程式註解全是中文、口吻一致，也符合這個推測。

## 二、故事設計

### 1. 三幕結構

程式註解自己把劇情分成三幕 ✅：

| 幕 | 標題 | 玩家在做什麼 | 對方能不能看到你的信箱 |
|---|---|---|---|
| 序 | （收件匣原本的信） | 人資、IT、行政、同事、經理寄來的日常信件，同時埋好之後要用的線索 | — |
| 一 | 被盯上 | 解開威脅信的暗號、照對方說的回信；發現資安組在偷偷聯絡你 | 能 |
| 二 | 假裝配合，暗中反擊 | 交出資安組準備的假底價、識破驗證碼騙局 | 能 |
| 三 | 抓人 | 資安組直接交代任務：查物流單、登入員工入口網、看門禁、問同事 | 不能 |

### 2. 謎題為什麼要藏起來：故事本身給了理由

這是整款遊戲最聰明的設計。

壞人看得到你的信箱，所以資安組不能直接寫信說「我們在幫你」。他們只能把訊息藏在宣導海報的編號、講座報名的回信、經理的更正版文件裡 ✅。等第二幕結束，資安組把外部存取切斷，第三幕的信就改成白話直說 ✅。

一般解謎遊戲常被問「為什麼要用暗號講話？」，這款用劇情回答了：因為有人在偷看。謎題的存在本身就是故事的一部分。

### 3. 謎題清單

| # | 信 | 解法 | 線索在哪 |
|---|---|---|---|
| 1 | 客戶「第四季採購數量確認」 | 每行第一個字連起來（藏頭） | 同一封 |
| 2 | 物流「十月出貨延遲說明」 | 錯字依序排起來，要你回工號 | 人資的打卡異常名單 |
| 3 | 廠商「十月份請款明細」 | Excel 第二個工作表裡，每句有一個字的顏色或大小不一樣 | 經理的「另函」密碼信 |
| 4 | 資安「資訊安全月報」 | 海報最下面的編號，用注音鍵盤打出來是中文 | 附件海報 |
| 5 | 資安「講座行前問卷」 | 上一封回信藏頭 → 去冒名客戶公司的官網看公告 | 虛構的公司官網 |
| 6 | 問卷第 2 題 | 比對寄件網址和官網網域，多了一個字母 s | 寄件人旁的灰字＋官網 |
| 7 | 客戶「交期與付款條件」 | 照片上紅筆圈的字照編號讀 → 對方要底價；要交的是資安組安排的假數字 | 經理信件串裡的更正版，編號又是注音密碼 |
| 8 | 顧問「報價比對表」 | 下載 Excel、填四格，總和要符合兩個條件 | 表格註記＋上一題的數字 |
| 9 | 顧問「補充確認事項」 | 打開加密 PDF，照實回答工期 | 謎題 3 的密碼 |
| 10 | 物流「系統對接確認碼」 | 對方要的確認碼就是你的登入驗證碼，不能給；按「這不是我」 | 另一封驗證碼信 |
| 11 | 資安「帳號遭冒用通報」 | 到物流官網查包裹號碼，看寄件樓層 | 謎題 2 那封信末的單號 |
| 12 | 同串 Re: | 雲端檔案的版本紀錄 → 最早版本是座位表 → 座位公告寫了事前給過哪三人 | 雲端頁＋行政公告 |
| 13 | 同串 Re: | 用臨時帳號登入員工入口網，查網段對照表 | 退信紀錄最下面的 IP |
| 14 | 同串 Re: | 在官網聯絡表單詢問真正窗口，等回信 | 表單要選對窗口才會成功 |
| 15 | 同串 Re: | 查門禁紀錄，證明頭號嫌疑人當晚不在公司 | 入口網門禁頁 |
| 16 | 同事「要不要一起訂便當」 | 私下打聽那晚看到什麼，不能提到資安組 | — |
| 17 | 同串 Re: | 同事傳來的夜間照片上，只有一桌亮燈，看座位牌號碼再查通訊錄 | 照片＋入口網通訊錄 |
| 18 | 同串 Re: | 「促銷內容」分頁裡有一封假廣告，優惠碼 `7F-SMALLROOM` 是見面地點 | 跟另一封真廣告比對寄件網址（o 換成 0） |

謎題 4 和謎題 7 用的「注音鍵盤亂碼」，是台灣人才看得懂的暗號。打字時忘了切輸入法，就會出現一串英數字，作者把這個日常經驗變成密碼。

### 4. 一封信同時是日常、也是線索

序章的 6 封信都「不用回」✅，但每一封都會在後面被用到：工號、密碼、座位表、IP 位址、同事的座位。作者在每封信的摘要第二層會提示「之後哪一封會用到」✅，降低玩家漏看的挫折。

廣告信也照這個原則：5 封真廣告各自有不同版型（咖啡店、購物網、航空、健身房、辦公設備）✅，讓第 18 題那封假廣告混在裡面不會太突兀。

### 5. 誤判有代價

第 15 題資安組會先說「我們懷疑是王經理」，請你同意或反駁 ✅。

- 回覆他的名字：劇情照樣往下走，但結局會多一段「王經理被叫去問了快兩個小時」，評等扣 20 分，結案表標成紅字「被你冤枉」✅
- 回覆「不是他」並說明理由：資安組承認「險些誤判」✅

這不是三選一的道德題。玩家要先查證才能下判斷，冤枉人的後果寫在結局裡。

### 6. 三種失敗，都能回到失敗前一步

| 失敗 | 觸發 | 結果 |
|---|---|---|
| 交出真底價 | 回信裡出現真正的投標總價 | 經理的責罵信，標案撤回 |
| 交出驗證碼 | 回信裡出現那 6 位數 | 帳號被停用 |
| 說溜嘴 | 問同事時提到資安組、調查、冒用 | 消息傳到嫌犯耳裡，證據被湮滅 |

失敗信寄到後，畫面下方出現紅色條「任務失敗」，按「回到失敗之前，重新來過」就回到送出那封信之前 ✅。不用整局重玩。

三種失敗剛好對應三個真實的資安教訓：機密不外流、驗證碼不給人、調查要保密。

### 7. 結局

最後一封是同事的八卦信，講剛剛會議室抓到人的經過，下面附一張結案卡 ✅：

| 欄位 | 內容 |
|---|---|
| 評等 | S／A／B／C，各配一句稱號，例如 S「資安組問你要不要轉調過去」 |
| 底價、冒用者、經理 | 三行結果，綠字＝做到、紅字＝沒做到 |
| 花費時間、看摘要次數、回錯信次數 | 數字 |

算法：100 分起算，每看一層摘要扣 4、回錯一次扣 6、冤枉經理扣 20；95 以上 S、75 以上 A、50 以上 B ✅。

## 三、互動方式

### 1. 介面就是遊戲

整個遊戲沒有「遊戲畫面」，只有一個模仿網頁信箱的介面 ✅。資料夾、標籤、星號、主要與促銷分頁、搜尋列、右側附加應用程式、儲存空間用量都有，大部分是裝飾，點了沒反應。

作者刻意不用真實品牌：logo 是自己畫的信封、介面文字只寫「郵件」，公司、客戶、物流、航空全是虛構名稱 ✅。登入頁的「忘記電子郵件」「隱私權」等連結點了會跳出提示，不會連到任何地方 ✅。

### 2. 提示偽裝成「AI 摘要」

每封信標題下面有一顆「✦ 摘要這封郵件」按鈕 ✅，長得像現在信箱內建的 AI 摘要功能。按一次給一層，再按變成「再摘要得更詳細一點」，最多 3～5 層：

- 第 1 層：這封信在講什麼
- 第 2 層：哪裡怪怪的
- 第 3 層以後：答案

連不用回的日常信、廣告信都有摘要 ✅。所以玩家按了也不會因此知道「這封有謎題」。提示系統藏在介面功能裡，不會打斷沉浸感。

### 3. 回信就是作答

| 動作 | 做法 |
|---|---|
| 作答 | 按「回覆」，在文字框打字，按傳送（或 Ctrl/⌘＋Enter）✅ |
| 對方回信 | 1.5 秒後出現在同一串 ✅ |
| 下一封信 | 4 秒後寄到，左下角跳「新郵件」通知，可以直接點「查看」✅ |
| 答錯 | 對方回一句不帶答案的回話；威脅者會冷冷地要你「依來信內容確認後再回覆」✅ |
| 答一半 | 對方會指出缺什麼，例如「名單似乎不完整」「七樓有大、小兩間會議室」✅ |

「答一半」的回饋是用角色口吻講出來的，讀起來像劇情，其實是在引導。

### 4. 假的檔案系統

附件點開會跳出檢視器 ✅：

| 類型 | 能做什麼 |
|---|---|
| Excel | 有欄列編號、公式列、底部多個工作表分頁 |
| PDF | 有密碼鎖，輸入對的密碼才看得到內容 |
| 圖片 | 全螢幕檢視，海報、照片、外箱都是 SVG |

最複雜的是第 8 題：玩家要先在檢視器按「下載」，再從右上角的下載清單用「本機」打開，才能在黃色格子填數字，合計會自動加總；回信時按迴紋針，從仿電腦的檔案選擇視窗挑出剛才那份檔案 ✅。選擇視窗裡還放了 3 個無關的假檔案當干擾 ✅。

### 5. 假的外部網站

信裡的連結會整頁切換到虛構網站，每個網站有自己的配色和版型 ✅：

| 網站 | 用途 |
|---|---|
| 冒名客戶的公司官網 | 最新消息、聯絡我們表單（選錯窗口會被退件，要重填） |
| 物流公司 | 包裹查詢 |
| 雲端分享頁 | 檔案資訊、版本紀錄 |
| 員工入口網 | 要登入；通訊錄可搜尋、門禁紀錄可選日期、會議室預約、IT 網段對照表 |

員工入口網的臨時密碼是「案件編號」，就寫在資安組每封信的主旨開頭 ✅。密碼也變成謎題的一部分。

### 6. 個人化

登入時輸入姓名（必填）和公司信箱（選填）✅：

- 所有信件裡的收件人名字換成你的名字，熟一點的同事只叫你名字的後一兩個字
- 有填公司信箱，所有公司內部寄件人的網域都改成你公司的網域

上班族在自己公司的電腦上打開，會看到「自己的公司」寄信給自己。這是代入感的來源，也是「上班也能玩」的偽裝來源。

## 四、程式概念

### 1. 整體架構 ✅

```
內容表
  MAILS   每封信一筆：寄件人、主旨、內文、附件、答案或判斷函式、摘要層、對方回覆、下一封
  VIEWS   附件內容：試算表格子、PDF 頁面與密碼、SVG 圖片
  SITES   虛構網站：每站一組頁面
  PEOPLE、DOOR、ROOMS   通訊錄、門禁紀錄、會議室預約
        ↓
規則
  send()     回信 → 比對答案 → ok／alt／fail／錯誤回話
  arrive()   新信寄到；標記 into 的信會接進舊的信件串
  recover()  重新整理時補回漏掉的回覆和下一封
        ↓
畫面
  renderList()  收件匣列表        renderView()  單封信＋信件串
  renderViewer() 附件檢視器       renderSite()  虛構網站
  renderFailbar() 失敗條          snack()       左下角通知
        ↓
底座：單一 HTML、localStorage、GitHub Pages
```

跟前幾款一樣是內容與引擎分開。差別在**內容表裡放的是「文件」**，不是事件卡或對話腳本。

### 2. 一封信的資料長什麼樣 ✅

每封謎題信就是一筆設定，主要欄位：

| 欄位 | 作用 |
|---|---|
| `answer` | 可接受的答案清單，例如工號可以寫 `HS-20417` 或只寫 `20417` |
| `check(text)` | 比較複雜的題目改用函式判斷，回傳 ok、alt、fail，或一句給玩家的回話 |
| `alt` | 另一種答法走另一條路（冤枉經理那題） |
| `hints` | 摘要層，由淺到深 |
| `reply` | 答對後對方回的話 |
| `next` | 答對後寄來哪幾封 |
| `failMail` | 這題答「錯得嚴重」時寄哪一封失敗信 |
| `into` | 這封信不另開新信，而是接在某封舊信的串裡（經理的更正版、同事的照片） |
| `tab: "promo"` | 放進促銷分頁 |
| `threat` | 對方是威脅者，答錯時用冷淡的語氣回 |

寫新謎題只要多加一筆設定，不用改規則。

### 3. 答案判斷：寬鬆但不亂放水 ✅

- 先統一格式：全形轉半形、轉小寫、拿掉空白和常見標點
- 玩家的回答**包含**正確答案、而且多出來的字不超過 8 個，就算對。所以「收到」「好的收到」都會過，但整段長文不會
- 數字題把回答裡 6 位數以上的數字全部抓出來比對，千分位逗號有沒有寫都可以
- 附件裡填的數字也會轉成文字併進回信一起檢查，所以「附上檔案、內文空白」也能過關

第 8 題的判斷最細：先擋掉真底價（失敗）、再檢查有沒有四個數字、合計對不對、維護費對不對，最後檢查前兩項加起來是否剛好等於差額，每一種錯都有自己的回話 ✅。

### 4. 存檔與回到上一步 ✅

- 每次答對前，把整個遊戲狀態轉成文字存進歷史，最多留 30 份
- 答到失敗時，把送出前的狀態另存成「檢查點」；按「重新來過」就整份換回去
- 對方回信和下一封信是幾秒後才寄到，這段時間重新整理會漏掉，所以載入時 `recover()` 會補上

### 5. 測試接口 ✅

程式裡有一份 18 題的順序表和每題的標準答案，搭配「跳到下一題」「回到上一題」兩個函式，可以一路自動解到底。按鈕目前已經從設定選單拿掉，但函式還留著 🔍（推測是開發時用，上線前藏起來）。

設定選單只剩「清除這個信箱的資料」，要連按兩次才會清除 ✅。

### 6. 美術做法 ✅

| 圖 | 做法 |
|---|---|
| 介面圖示、logo | SVG 路徑 |
| 5 封廣告信 | 各自一段 HTML，自己的字型、配色、版型 |
| 資安海報、外箱照片、講座白板、入場券 | SVG 畫的，線索字直接寫成 SVG 文字 |
| 同事的夜間辦公室照片 | **AI 生成的 JPEG 當底圖，再用 SVG 疊上三塊座位牌** |

最後一項很值得學：AI 生圖寫不好中文和編號，作者就讓 AI 只畫氣氛，關鍵線索（座位牌號碼 7F-E05、E06、E07）用程式疊上去。亮燈那桌的牌子是淺色、其他兩桌是暗色，字永遠清楚，要改號碼也只改一行 ✅。

### 7. 手機與深色模式 ✅

- 860 像素以下收掉左側資料夾，600 像素以下改成兩行的列表
- 跟著系統切換深色模式，顏色全部寫成變數
- 10-20 的 commit 專門修手機版的促銷分頁和工具列跑版

文字輸入多，手機上玩得動，但打字比電腦辛苦 🔍。

## 六、Pei 可以借用的

### 先講適用對象

原作是上班族的辦公室題材，有威脅、勒索的情節，文字量也大，**不適合讓三到六年級直接玩**。不過情節沒有暴力畫面，資安知識（網域比對、驗證碼不給人、不轉寄機密）對五、六年級的資優生剛好。

### 建議借用

1. **「為什麼要藏暗號」先用劇情交代**：情緒偵探社或之後的解謎遊戲，先設計一個「不能直說」的理由（例如委託人不好意思開口、紙條會被別人看到），謎題就不會像硬塞的考題。
2. **摘要式分層提示**：每個案件放一顆「偵探筆記」按鈕，第 1 層講重點、第 2 層講哪裡怪、第 3 層才接近答案。沒有謎題的地方也放，學生按了不會被暗示「這裡有東西」。
3. **答一半時用角色口吻引導**：情緒命名錯了，委託人說「我不是生氣，是覺得很丟臉」，規格書已經有這個想法；可以再細分成「方向對、詞不夠精準」「完全不對」兩種回話。
4. **失敗只退一步**：「回到失敗之前，重新來過」比整局重玩友善得多。情緒偵探社的闖關、校園溫度計的選項，都可以存一份檢查點。
5. **誤判要付代價，而且寫進結局**：「冤枉人」這條線很適合 SEL。例如在情緒偵探社加一題：先入為主地認定某同學是故意的，結案報告就多一行「被你誤會的人」。
6. **AI 生圖當底、程式疊線索**：ChatGPT 生的場景圖不必有字，名牌、標籤、編號都用程式疊上去。之後要改線索不必重新生圖。這也解決了 AI 生圖常把中文寫錯的問題。
7. **答案判斷寬鬆化**：統一全半形、拿掉標點、允許多幾個字。學生打字習慣差異大，這幾行規則能省掉很多「我明明答對了」的抱怨。
8. **測試用的答案表**：每題寫一個標準答案，配一個「自動解到下一題」的函式，Claude 每次改完可以一路跑到結局確認沒卡關。這就是回歸測試清單的程式版，跟五層骨架第⑤層一致。

### 也許可以開一款新遊戲（交 Pei 決定）

**仿「學校聯絡簿／班級信箱」的防詐解謎**，給五、六年級。

- 介面模仿一個虛構的班級訊息 App
- 有人假冒老師或同學傳訊息，要學生的帳號密碼、驗證碼、遊戲點數
- 學生要比對頭像、帳號拼字、說話習慣，向真正的老師求證
- 注音鍵盤密碼這種在地暗號，學生會覺得很新鮮

這個主題同時接得上資訊素養、防詐騙宣導，也可以當資優生的獨立研究題目：讓他們自己設計一封「藏了暗號的假訊息」給同學解。

### 建議先不要

1. **大量打字作答**：平板打中文慢，國小生容易卡在輸入而不是推理。改成點選詞卡、拖拉排序，只在少數關卡打短答案。
2. **18 題、跨 20 幾封文件的規模**：一節課 40 分鐘，學生記不住這麼多線索。建議 6～8 題、文件 10 份以內。
3. **模仿真實信箱或通訊軟體到可以亂真**：原作已經刻意不用品牌名稱。學生版更要清楚標示「虛構」，避免學生把遊戲裡的操作帶去真實帳號試。
4. **輸入真實姓名**：原作登入要打姓名，只存在瀏覽器。學生版改成「輸入偵探代號」，不收真名。
5. **威脅、勒索情節**：換成「有人冒名惡作劇」之類國小生能處理的強度。
