## 一、一句話介紹

你是普通班的學生，今天換成用班上某位同學的腦袋過一天。你會發現他上課為什麼一直舉手、作品為什麼一直重畫、從資優班回來為什麼一臉茫然。第二輪，班上的人做了幾個小調整，同一天變得不一樣。

## 二、已確認（2026-10-23）

- 玩家：普通班同學
- 畫面：2D 俯視 RPG，不做 3D
- 角色特質要符合資優生的真實樣貌，目的是讓同儕了解資優生的需求
- 玩家視角：變成資優生本人過一天，看得到他的念頭
- 「資優」兩個字：玩的時候只寫感受，結算頁才說明這是部分資優生的經驗；「從資優班回原班」那一幕照實寫
- 對象：三到六年級普通班同學，文字以中年級讀得懂為準
- 部署：daimg49-gif 帳號下開新 repo（建議名稱 `same-classroom`）

## 三、教學目標

| 學生玩完要帶走的 | 遊戲裡怎麼做到 |
|---|---|
| 資優生不是什麼都會，也不是成績好而已 | 每位角色都有明顯的弱項（字寫很慢、體育普通、不會聊同學的話題） |
| 有些讓人看不順眼的反應，背後有原因 | 玩家用他的腦袋過一天，看見「念頭」和「說出口的話」不一樣 |
| 同學一句話、一個小動作就有差別 | 第二輪支持模式並排比較；結算每個時刻都寫「同學可以」 |
| 困難和長處常常是同一件事 | 結算頁的「另一面」對照表 |

## 四、角色特質的依據

角色只放研究上有支持、而且同學在教室裡看得到的特質。兩條原則：

1. **不把資優生寫成同一種人。** 兩位主角特質不同，各自有弱項。
2. **研究結論不一致的地方照實寫。** 不把「資優生都很焦慮、都完美主義」當成事實。

| 特質 | 遊戲裡的樣子 | 依據與保留 |
|---|---|---|
| 學得快、已經會了還要等 | 老師講第三遍，「卡住條」慢慢上升 | 學業進度落差是資優教育採用課程壓縮、加速的主要理由 |
| 非同步發展：想法跑在手、情緒、社交前面 | 腦中句子很長，手寫跟不上；想聊的話題跟同學不一樣 | Columbus Group（1991）把資優定義為「進階的認知能力和高強度結合而成的非同步發展」，並指出能力越高、落差越大。這份定義出自 1991 年在俄亥俄州 Columbus 的會議手稿，沒有正式出版 |
| 感受強烈、在意公平 | 別人覺得沒什麼的事，「心情浪」升得很快 | 來自 Dąbrowski 的過度激動特質（overexcitabilities），Piechowski 引進資優教育。後設分析有發現資優組分數較高，但各研究結果差異大，教師頁要寫「研究結論不一致」 |
| 對自己要求很高 | 美勞作品一筆畫歪就想重來 | Stricker 等人 2020 年在 *Educational Psychology Review* 的後設分析（10 篇研究、4,340 名學生）：資優生在「追求高標準」略高於一般學生，在「擔心犯錯」這種負面的完美主義上沒有差別。所以遊戲只寫「要求高」，不寫「很焦慮」 |
| 抽離到資優班上課 | 回原班時錯過換座位、錯過剛發的通知，被說「你又不在」 | 分散式資優班的實際安排，台灣普通班同學最常看到、也最容易誤會的時刻 |

## 五、兩位主角與時刻（初稿）

名字都是暫定，老師確認沒有和班上學生撞名後再定。

### 第一關：想得太快的一天（主角：品睿）

數學很快、問題很多，字寫很慢，體育普通。

| # | 時刻 | 體驗模式 | 支持模式 | 同學可以 |
|---|---|---|---|---|
| 1 | 數學課講第三遍 | 卡住條上升；腦中冒出「如果除數是 0 會怎樣？」；舉手被說「等一下再問」 | 老師給延伸任務卡；問題貼在「問題停車場」 | 他提問時不要翻白眼說「又來了」 |
| 2 | 小組作業 | 你一下就想到做法，組員還在讀題；寫完後組員說「那你自己做就好」 | 每人先說一個想法再動筆 | 跟他說「你先講思路，我們一起寫」 |
| 3 | 從資優班回原班 | 座位換了、通知單發完了，沒人告訴你 | 小老師在桌上留一張紙條 | 回來時告訴他剛剛發生什麼事 |
| 4 | 下課聊天 | 想聊恐龍滅絕的新說法，大家在聊卡牌 | 有人問「你最近在看什麼？」，你也加入卡牌 | 問他在想什麼，也邀他加入你們的話題 |
| 5 | 寫作文 | 腦中句子很長，手寫跟不上；被說「資優生字這麼醜」 | 老師允許先口述或打字 | 不要用「資優生」當嘲笑的開頭 |

另一面：好奇心、很快看出規律、能把不同的東西連起來。

### 第二關：感受太強的一天（主角：可晴）

畫畫很好、很在意公平，數學普通。

| # | 時刻 | 體驗模式 | 支持模式 | 同學可以 |
|---|---|---|---|---|
| 1 | 美勞課 | 一筆畫歪想重畫，時間一直流走 | 老師先說「今天是草稿」 | 不要催他「隨便畫一畫就好」 |
| 2 | 發考卷 | 考 92 分，同學說「你不是很厲害嗎？」，心情浪升高 | 同學改問「哪一題最難？」 | 不要拿「資優」比分數 |
| 3 | 躲避球 | 對方踩線沒人管，你一直在意，被說「玩遊戲幹嘛那麼認真」 | 班上有固定時間討論規則 | 聽他把理由講完 |
| 4 | 國語課讀到流浪動物 | 你難過到下一節，同學說「又不是你的狗」 | 老師說「有感覺的人可以寫下來」 | 不要笑他太敏感 |
| 5 | 當小老師 | 一直被問問題，自己的作業寫不完 | 小老師輪流當 | 先自己想一下再問 |

另一面：細膩的觀察、強烈的正義感、作品的完成度。

## 六、玩法

| 項目 | 做法 |
|---|---|
| 地圖 | 一層樓：原班教室、走廊、資優班教室、操場、美勞教室；俯視、點選走動，平板觸控 |
| 時間 | 一天從早自習到午餐，約 8 分鐘一關 |
| 數值 | 第一關「卡住條」、第二關「心情浪」，加上「時間」；只用文字段落顯示（例如「有點煩／快坐不住了」），不顯示數字 |
| 念頭與說出口的話 | 念頭用雲朵框、對白用一般框，玩家看得到他心裡在想什麼 |
| 選擇 | 照範本原則：取捨題，沒有明顯的壞選項；好選項要付代價 |
| 第二輪 | 支持模式＝換一組參數（老師與同學的做法、事件強度、時間壓力），劇情程式只寫一份 |
| 結算 | 時刻卡三欄（發生什麼／為什麼／同學可以）＋另一面對照表＋兩輪並排比較 |
| 暖身 | 開頭一個單畫面：老師說一句「這題大家再算一次」，切換「一般同學聽到」「品睿聽到」「可晴聽到」三種內心話 |

## 七、技術做法（積木架構法）

| 積木 | 做法 |
|---|---|
| 入口（展示） | 2D 俯視地圖、程式畫的圓身人物、雲朵念頭框；平板橫向，按鈕至少 56 像素 |
| 守門（邏輯） | `say()`／`think()`／`choose()` 劇本函式；兩組模式參數；數值只在後台算 |
| 地基（部署） | 單一 HTML、localStorage 只記「玩過哪幾關」、GitHub Pages 新 repo |
| 工具箱（資料） | 角色表、時刻表、支持參數表、另一面對照表、討論題 |
| 測試積木 | 兩關 × 兩種模式 × 三種選法自動跑完；手機 390 像素截圖 |
| 錯誤記錄積木 | 角落顯示錯誤代碼＋裝置資訊 |

## 八、需要特別小心的地方

1. **公開身分**：班上的資優生只有幾位，同學會拿遊戲角色對號入座。主角名字、外觀、興趣要避開班上實際學生；開頭與結尾都寫「角色是虛構的，不代表任何一位同學」。
2. **變成「資優生好可憐」**：每一關都有主角做得很好、很開心的時刻，不只寫困擾。
3. **變成「資優生比較厲害」**：每位主角都有明顯弱項，結算不比較能力。
4. **資優生本人在場玩**：教師頁提醒老師，資優生可能不想在全班面前被看見，討論時不點名、不請他現身說法。

## 九、待老師決定（初版當時）

1. 主角暫定名「品睿」「可晴」有沒有和班上或資優班學生撞名（已確認不用換）
2. 第五節兩關各 5 個時刻，要刪、要換、要加哪些
3. 遊戲名稱《同一間教室》可以嗎
